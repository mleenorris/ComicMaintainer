Settings

Configure processing, delivery, integrations and maintenance for this ComicMaintainer instance.

These are server-wide settings and can only be changed by an administrator. Your personal appearance preference below is still editable.

Appearance

Theme and personal display preferences.

Controls which view the library loads into when you first open the site.

Access

Sign-in and guest access.

Disabled by default. When disabled, only an administrator can create accounts, so anyone who can reach this server cannot sign themselves up. Leave this off unless you intentionally want open sign-ups.
Used as a fallback when a series has no per-series language override. The library will prefer the first cached title or alias in this language. Changing this also enqueues a background job that rewrites every affected file's ComicInfo.xml <Series> to match (requires normalization to be enabled).

Watcher

Automatic processing of new files.

The file watcher automatically starts when either rename or normalize is enabled below. It monitors the directory for changes and automatically processes new or modified files based on your selected options.
When enabled, files will be renamed based on the filename template during processing.
When enabled, metadata will be normalized during processing.

Send to Ereader

Email delivery to Kindle and other devices.

Configure SMTP delivery and saved ereader devices.
Leave blank to keep the stored password.
Leave unchecked for the common submission port 587, which upgrades the connection with STARTTLS.
Only enable for a trusted local relay that offers no TLS. Credentials and attachments are sent unencrypted.

Automated Error Reporting

Share redacted error reports with the developers.

When enabled, errors logged by this instance are deduplicated and filed as issues on the ComicMaintainer project repository, where they reach the people who develop it. Paths, email addresses and credentials are redacted before anything is sent. This is off by default; nothing leaves this machine until you turn it on and supply a token.
Fixed: reports go to the project's own repository, which is the only place anyone can act on them.
Use a fine-grained token with issues: write on that repository only.
GitHub login to assign new issues to. Set this to the coding agent's login to have it start work automatically. If the login cannot be assigned, the issue is still created unassigned.
An already-filed failure never gets a second issue. This is how long to wait before adding a "still happening" comment to the existing one.
Save your settings first, then send a harmless test report to confirm the token works.

Log Rotation

How much log history is kept.

When the log file reaches this size, it will be rotated. Up to 3 backup files will be kept. The new size only takes effect after the service restarts — use Restart Service below to apply it immediately. Note: Can also be configured via the LOG_MAX_BYTES environment variable (in bytes).

Database Cleanup

Pruning of old processing records.

How often the database should be cleaned of stale entries for files that no longer exist. Set to 0 to only run on startup. Changes take effect on restart. Recommended: 12 hours (default) or 24 hours for less frequent cleanup.
Manually trigger database cleanup to remove stale entries for files that no longer exist on disk.

Backups

Database backups: create, download, restore and delete.

Restart required. A database restore is staged and will be applied the next time ComicMaintainer restarts.
A restore is validated and a safety backup of the current database is taken first; it is applied when ComicMaintainer restarts. Backups contain password hashes and stored credentials, so keep downloaded copies private.

Filename Format

How processed files are renamed.

Configure how files are renamed when processed. Use placeholders like {series}, {issue}, etc.

Available placeholders:
  • {series} - Series name
  • {issue} - Issue number (padded based on settings, default 4 digits, e.g., 0001, or 0071.4 for decimals)
  • {issue_no_pad} - Issue number (no padding, e.g., 1, or 71.4 for decimals)
  • {title} - Issue title
  • {volume} - Volume number
  • {year} - Publication year
  • {publisher} - Publisher name
Example: {series} v{volume} #{issue_no_pad} ({year})
Note: File extension (.cbz or .cbr) is automatically preserved
Current format:

Issue Number Padding

Zero-padding for issue numbers.

Controls how many digits the {issue} placeholder uses (default: 4). For example, with padding set to 4, issue 5 becomes 0005, with padding 3 it becomes 005, and with padding 0 it remains 5. Note: This only affects the {issue} placeholder. Use {issue_no_pad} for unpadded issue numbers regardless of this setting.

Series Covers

Series cover artwork.

When enabled, the cached provider/user series image is also written into the first issue's archive as a cover.<ext> entry, so external readers (Komga, Kavita, etc.) show the same cover. This rewrites the comic archive in place; the write is idempotent and only targets writable CBZ archives. The cover shown throughout ComicMaintainer always uses the downloaded provider image regardless of this setting.
When enabled, a copy of the cached series cover is written into every on-disk folder that contains files for the series as a cover.<ext> sidecar, so file managers and external readers can display it. Set to disabled to leave series folders untouched.
When enabled, external metadata refreshes also try to download a series cover image from the chosen provider. Disable to keep metadata-only refreshes (e.g. for limited-bandwidth deployments).
Maximum size of a stored series cover image. Larger downloads are downscaled to fit under this limit. Default: 5 MB.
Hard ceiling for the raw payload fetched when downloading an external cover. Payloads above this are rejected; those between the stored limit and this ceiling are downscaled. Must be greater than or equal to the stored cover size. Default: 25 MB.
Maximum width or height, in pixels, of a stored series cover image. Oversized downloads are resized (preserving aspect ratio) so their largest dimension is at most this value. Default: 2048.

External Series Metadata

Synopsis and metadata providers.

Master switch. When enabled, ComicMaintainer can look up alternate series titles from the providers configured below so variants can be grouped together in the series library view. Lookups are manual — use the Library page's Metadata → Refresh All External Metadata button or the per-series Manage Names action to populate the cache. Changes take effect after restart.

ComicVine (US comics)

Leave blank to disable ComicVine lookups. The key is stored in user settings on this instance.

MangaDex (manga)

Looks up canonical titles and alternate localizations from MangaDex. No API key required.

AniList

Queries AniList for both Manga (Japanese origin) and Manhwa (Korean origin). No API key required.

Suwayomi Downloads

Fill missing issues from a Suwayomi server.

Lets ComicMaintainer ask a Suwayomi server to download the issues a series is missing. Suwayomi saves them to its own download directory, so mount that directory inside the watched directory for the new files to be picked up.
Save your settings before testing.

Danger Zone

Irreversible actions.

This will permanently delete all processing information including:

  • All file processing states (processed, renamed, normalized)
  • Complete processing history
  • All database records

This action cannot be undone! Your actual comic files will NOT be deleted.

Changes apply when you save. Some take effect after a restart.

About Comic Maintainer

Comic Maintainer

Version: Loading...

Description

Comic Maintainer is a service that automatically watches a directory for new or changed comic archive files (.cbz/.cbr), tags them using ComicTagger, and manages duplicates. It provides a web interface for managing and processing comic files in your watched directory.
